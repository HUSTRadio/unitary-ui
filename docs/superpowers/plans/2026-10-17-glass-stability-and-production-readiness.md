## 2. Glass 运行时修复

主要修改 `src/lib/glass-runtime.ts`，不改变材质数学或公开 API。

- 正确退出材质身份：观察选择器涉及的身份属性；元素不再匹配、变为不可增强或离开文档时，取消发布请求、解除尺寸观察、清理私有样式并释放引用。异步解码完成后再次核对身份和请求版本，禁止旧结果恢复到元素上。
- 共享构建中任务：沿用完整几何与光学缓存键，同键只构建一对贴图。逐元素保留订阅和版本；单个元素取消不影响其他使用者，失败后允许重试，全部取消后不得遗留 filter。
- 合并失效调度：同一帧的完整扫描只执行一次；尺寸变化直接更新对应表面。继续忽略运行时自身的私有样式和 SVG 内部变化。
- 保留作者 CSS 联动：class/style、主题、全局 token 和辅助设置变化仍可触发合并后的全局重算，不假定兄弟选择器或 `:has()` 不会影响材质。

先建立回归和优化前基线，再实施修复。全局扫描成本与既有 25ms 波动之间不预设因果关系。

## 3. 性能与真实用途验收

### 可维护的性能测量

将现有 scratch 探针收敛为正式定向测量工具，使用生产产物和可选测试 fixture，不进入常规产品路由，不增加运行时依赖。

- 分开记录材质启用、首次真实输入、稳定交互、稳定滚动和空闲。首次输入不使用隐含的 700ms 预热；稳定阶段明确预热后分别采集至少 5 秒。
- 场景采用 Clear 媒体控件、Regular Toolbar、Dense Select 列表。按钮和选择操作正常提交状态，不再拦截 click；fixture 保持操作前后几何一致。
- 桌面基准 1280×900、DPR 1/2、浅深主题；各用途分别比较 Solid、Aero、对应 Glass，每条件三次独立运行，固定种子轮换顺序。390×844、DPR 2 的移动 CSS 回退另行测量，不冒充移动 SVG。
- 桌面使用原生鼠标、键盘和滚轮输入；移动场景使用触摸输入。新 Portal 的首次构建单独计数，不与已打开表面的稳定交互混算。
- 保存原始 RAF 时间序列、输入与状态提交时间、长任务、滚动距离、renderer、贴图构建次数、采样器数量、浏览器版本、视口、产物摘要及采样/墙钟时长。每次运行独立落档，禁止成功覆盖失败。
- 稳定交互和滚动每次均须 P95≤20ms、无超过 50ms 长任务；几何及参数不变时不得重建贴图。移除测试采样器后，空闲一秒不得存在持续 RAF 循环。
- RAF 指标仅称页面帧调度节奏，不当作 GPU 呈现时间或标准 INP。若 Solid 对照也失败，标记测量条件不稳定，保留所有失败并诊断。
- 若构建阶段可复现主线程长任务，采用不超过 4ms 的计算分片和异步 PNG 编码；增强就绪前保留 CSS 回退。维持现有贴图上限和光学质量，不降低折射、分辨率或放宽阈值过关。

### 实际组件与生命周期

- 验证 Clear 独立衬层、Regular 导航/Toolbar、Dense 实际 Select、菜单、Modal 和 Drawer。
- 按真实宿主检查有效参数、Portal、作者覆盖/reset、单次采样。已有遮罩边界、尖角等场景允许既定 CSS/Solid 回退，不要求所有浮层启用 SVG。
- 补齐身份移除、类型切换、解码期间取消、同键并发、不同键隔离、StrictMode 重挂载、多个根共享管理器，以及最后一个根卸载后的订阅和资源清理。
- 检查 hover、pressed、selected、focus、disabled 与事件取消；正文合成对比度至少 4.5:1，必要控件标识至少 3:1。
- 执行此前未包含的强制颜色恢复、作者样式优先及全局浮层回归。增加真实 Firefox/WebKit 回退冒烟；修改 UA 的 Chromium 仅作为能力门禁测试。

两个 RAF 的修订矩阵在 12 个已完成样本中仍出现一次失败，已停止继续无效测量，并保留 `interrupted.json` 和全部已完成样本；未生成通过结果。后续发现回调可能携带解码前的旧时间戳，补充时间戳检查后仍不能证明 GPU 工作完成。

离屏画布试验的功能、类型与 90 个浏览器回归通过，但六次正式性能短测仍有一次 95ms 冷任务。进一步追踪在离屏路径中捕获约 56ms 的主线程任务，其中约 55.65ms 是合成提交等待，线程 CPU 约 0.95ms。因此撤回该实现、对应测试和 Changelog，生产运行时恢复为 `3d79459a` 的已验证版本；未采用新的编码器或依赖。

## 9. 初始照片呈现竞态与最终测量

跨线程追踪显示，上述约 56ms 等待期间，GPU 图像缓存存在约 185ms 的 JPEG 解码任务，包含约 105.85ms 的 JPEG YUV 解码；它在材质启用之前已经启动。`image.decode()` 返回和两个 RAF 均不足以排除这一初始场景工作。原始分析保存在 `.scratch/glass-stability/compositor-wait-analysis.json`，不能把这段等待算成位移数学函数的 CPU 执行时间。

两个独立的 12 次交替对照保留完整证据：

- JPEG 场景捕获后再首次启用材质，6/6 次无冷长任务；不捕获的 6/6 次有长任务，最高 106ms。捕获前后均为 Solid、零贴图／编码／SVG。该试验会改变 GPU 初始状态，**仅用于诊断，未作为正式验收方法**。
- 不使用截图，等待背景照片自身的 LCP 呈现记录后再启用，6/6 次无冷长任务；只等待解码和 RAF 的 6/6 次有长任务，最高 107ms。两组均使用原产物和原光学参数，未预先启用 Glass。

正式测量改为版本 4：单独记录 `scene-load`，在 Solid 下等待字体、图像解码以及**相同照片 URL、相同背景元素**的有效 LCP 呈现记录，然后首次启用材质。不使用截图或固定延时；检查就绪时为 Solid、零贴图、零编码、零 SVG，缺失或不匹配即失败。依据 [LCP 规范](https://www.w3.org/TR/largest-contentful-paint/)和 [Chromium 呈现回调实现](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/paint/timing/paint_timing.cc)划分场景边界，不把 LCP 当作 GPU 耗时测量。

探针同时观察 HTML／Offscreen 编码，构建区间延伸到位移 PNG 解码完成；缺少构建／解码、一对 PNG 或唯一桌面 SVG 采样器证据不得通过。保留所有阶段的原始 RAF，增加帧间隔中位数以识别宿主调度节奏变化。当前观测节奏与早先不同，**不得把跨时段 P95 差异称为代码提速**。新增门禁单测 8 项通过，测试类型和静态检查退出 0。

版本 4 的桌面深色 DPR 1、浅色 DPR 2 及移动 CSS 回退短矩阵 3/3 通过。随后在原生产产物上完成完整矩阵，结果如下。旧失败全部保留，不宣称生产代码降低了照片加载或 GPU 初始化成本。
