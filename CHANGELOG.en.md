## [Unreleased]

### Added

- **SkeletonMask skeleton overlay component**: give a region a skeleton template and the `masked` flag swaps the whole block to skeleton, `unmask` swaps back to the real interface. Composing with `Skeleton` instead of conditional rendering is deliberate — the `skeleton` template stays mounted and the real content keeps its box via `visibility: hidden` while masked (`inert` plus `aria-hidden`, so it never enters the accessibility tree and cannot be tabbed into or clicked), which means one single box across the swap and no width jump. The container carries `aria-busy` and the accessible name from `label`, with an optional `liveRegion` completion announcement (off by default so several masked regions do not repeat it). It is a framework extension with no official Geist counterpart and is filed under the Skeleton docs page, sharing that page's guide, API reference, and corpus; `SkeletonMask` and `SkeletonMaskProps` are exported from the package root, and its two usage examples (Usage / Controlled toggle) also render as Skeleton demo sections.

- **Table outlined-frame demo**: adds an `Outlined table` (带外框表格) example built from `TableRoot frame="outline"` + `colorScheme="bordered"`, showing the real container outline. It differs from `Row dividers` (row separators only, no `TableRoot`) by exactly that frame, so the pair isolates what `frame` controls; `frame` previously appeared only as a side attribute of other demos and had no dedicated demo of its own.
- **ContinuousSurface pre-merge corrections**: removes the competing background radius after clip-path enhancement; measures and observes the local border-box independently of ancestor transforms; uses a normalized SVG clip for the responsive superellipse demo; pins high-exponent curve endpoints and validates sample counts before special-case paths. Adds pixel, transform, border-resize, and responsive hit-testing regressions.

- **Shape families and continuous curvature**: extends the fixed radius scale with `--radius-2xl/3xl/4xl/5xl` (16/20/24/28px) and adds `--radius-concentric-inset` / `--radius-circle` / `--radius-capsule` semantics; adds `src/lib/continuous-corner.ts` (independent power-family continuous curvature: `cornerCurvePoints` / `continuousCornerPath` / `superellipsePath` / `useContinuousCorners`, with p=2 degrading exactly to circular arcs) plus the `ContinuousSurface` component, all exported from the package root; bilingual guides, a runnable example, API reference, and LLM pages cover it (86 routes × 2 locales = 172 pages). The default continuous exponent is 3; all curve values are Unitary team values — no platform-brand names and no paths copied from platform resources; attribution lives in `docs/design/corner-and-typography-tokens.md`.

### Changed

- **`BreadcrumbProps` is now a discriminated union (type change)**: `type="text"` (the default) continues to extend `<nav>` attributes, while `type="menu"` now extends `<div>` attributes. Previously the menu variant accepted both `<nav>` and `<div>` props, so the rendered `<div>` received invalid attributes and clobbered caller-supplied `role` / `aria-*`; each variant now exposes only the attributes it actually renders. Callers using `type="menu"` with `<nav>` attributes must switch to `<div>` attributes or drop the extras.
- **Feedback interaction and public API**: the default variant now opens a 340px Popover from a 32px secondary trigger, while `type="inline"` uses a 274×48 rating capsule that expands in place to 336px; keyboard rating navigation, `dryRun` / `onSubmit` submission semantics, and blue rating states now match the implementation, while the standalone `RatingPill` keeps its local four-tone extension.
- **Feedback topic contract completed (API change)**: the topic selector previously lived only in internal state, so `onSubmit` could never observe the chosen topic — the selector renders only in the default Popover variant, and the sole official demo carrying a Select is `dryRun`, leaving no path where a topic was observable. `onSubmit` now takes a fourth `topic?: string` argument, and the component adds `topics` (a non-empty array renders the selector without needing `showTopics`), controlled/uncontrolled `topic` / `defaultTopic` / `onTopicChange`, and `includeTopicInMetadata` (defaults to `false` so `metadata` stays byte-identical to what the caller passed). The Inline variant deliberately renders no topic selector and ignores `showTopics` / `topics`. The `FEEDBACK_TOPICS` topic-list constant is exported only from the `feedback` module, while the package root still re-exports `Feedback` alone, so consumers keep reaching the official topic list through `topics` / `showTopics`. Callers relying on the old implicit topic-into-metadata merge must use the fourth argument or opt in with `includeTopicInMetadata`.
- **Platform-specific link icon placement**: GitHub, GitLab, Gitee, Codeberg, Bitbucket, Forgejo, and SourceHut links now place the brand icon before the label by default and continue to omit the redundant ExternalLink indicator; generic HTTP(S) links retain a trailing generic indicator, while an explicit `iconSide` always wins.
- **`LoadMoreButton` color semanticization**: migrated 12 hard-coded gray raw literals in `src/components/ui/load-more-button.tsx` (`#f2f2f2` / `#8f8f8f` / `#1a1a1a`, including 6 `dark:` variants) to 2 theme-aware semantic tokens (`gray-100` in 5 places, `gray-700` in 3 places), removing all 6 `dark:` variants while keeping the light/dark render output visually equivalent.
- **Package-root surface cleanup (breaking)**: `ExpandPanel`, `Grabber`, `PhoneStatusBar`, and `PhoneSafariChrome` are no longer exported from the package root and remain implementation details of HamburgerMenu, BottomSheet, and Device; Navbar, SidebarNav, Footer, and RatingPill now expose their public props/data types, and unreachable API registry data was removed.
- **Device is now the canonical device-frame documentation surface**: the former Phone page is migrated to Device with iPhone, Pixel, Galaxy, and iPad models; the old `/components/phone` URL keeps a compatibility mapping, while the runtime `Phone` alias remains for migrating existing iPhone 17 call sites.
- **Font stack strategy**: all @font-face rules renamed with Subset suffixes; system-first font stacks (machines with OPPO Sans / HarmonyOS Sans installed hit the system fonts with zero downloads, others fall back to self-hosted tiered subsets); manual tier declaration via root `data-font-tier="oppo|hmos|system"`; tier switches re-measure with a 120ms debounce (idempotent).
- **Table default alignment (breaking)**: removed implicit `last:text-right` from `TableHead` / `TableCell`; everything is left-aligned by default, matching official Geist. Numeric columns relying on the old implicit right alignment must now use explicit `align="right"` or `text-right`.
- Publish boundary: `files` now includes `LICENSE`, `LICENSE.zh-CN.md`, and the bilingual third-party notices; font subsets are distributed with `dist` (license status in THIRD_PARTY_NOTICES).
- The library package now externalizes npm dependencies, omits sourcemaps, and removes stale demo/app artifacts. All 15 processed font subsets remain included; the Maple OFL-1.1 text ships with the package, while the README explicitly discloses the OPPO Sans / HarmonyOS Sans redistribution-evidence risk.
- The LLM generator now selects an available port and starts an exclusive preview for every run instead of reusing a potentially stale service; generated Markdown remains formatter-stable.
- `AGENTS.md` is now a portable repository-level LLM entry point that links the canonical source, Geist docs, and `docs/llm/index.json`, without personal environment details, signing identities, or bindings to a specific Agent tool.
- The versioned agent task package moved to top-level `.agents/` with no legacy-directory compatibility alias; runner, schema, prompt discovery, pre-push impact paths, contract tests, and Git ignore/line-ending policy now use the new path.
- Pre-push now combines README screenshot drift detection with the existing documentation/LLM update gate in one orchestrator: real changed paths are the sole gate decision, while Angular/Conventional Commit type and scope are diagnostic signals that cannot override path impact. Screenshot drift regenerates managed files and aborts the push; every blocked push identifies the incomplete operation and prints recovery steps for human review, commit, and retry.
- Living-styleguide examples now use the current component APIs and realistic action semantics. The bounded `docs-update` task may synchronize `src/App.tsx`, `src/examples/**`, and managed screenshots, with zero screenshot drift enforced as a deterministic validator.
- **AI docs pre-push delivery**: docs-update prompts above 8000 characters are now delivered through `codex exec`'s stdin channel, fixing `ENAMETOOLONG` from Windows `CreateProcess` command-line limits on first push.
- **LLM task runner switched to Pi**: the `.agents/runner.config.json` `agent` moves from Codex (`codex exec`) to the Pi Coding Agent (`pi --print`), with the config fields now `piCli` / `provider` / `model` / `thinking` / `ephemeral`; `scripts/lib/llm-task-runner.mjs` emits the fixed `pi --print` argument template and rejects a substituted executable, defaulting to the `deepseek/deepseek-flash` execution model; the Codex-only `sandbox` / `approvalMode` config keys and their `--ephemeral` / `--approve-for-me` / `-C` argument shapes are removed. The fixed template adds `--no-extensions`: extension-provided MCP servers keep stdio open after the answer, so `pi --print` never exits and pre-push stalls (measured: default mode did not exit within 90s, 3s with the flag).

### Fixed

- **Clipped-surface shadows now use `surface-shadow` (visual change)**: a surface clipped by `clip-path` cannot cast a correct `box-shadow` — `clip-path` clips the element's own shadow, while moving the `box-shadow` to an outer wrapper draws the wrapper's own rounded rectangle, so once the shapes differ (a superellipse) the shadow decouples from the body and exposes a rectangular backing. Adds the `@utility surface-shadow` (two `filter: drop-shadow()` layers generated from the rendered child's alpha, so it hugs the clipped outline), which must live on the outer wrapper: a `filter` on the clipped element itself is clipped away by `clip-path` too. `drop-shadow()` takes `<length>{2,3}` and has no spread parameter, so copying `box-shadow`'s `0 8px 16px -4px` makes the parser drop the whole `filter` declaration (lightningcss reports nothing; only the browser rejects it); the 1px hairline ring that `material-*` draws with spread is therefore unreachable and the trade-off is recorded in the comment. Component comments, the corner-token design doc, the `ContinuousSurface` example, and the bilingual guides were updated together, backed by a CSS contract test and real-browser assertions.
- **Grid guide and frame pixel fixes (visual change)**: item-by-item fixes driven by on-page forensics at `#/grid`. (1) The guide color moves from the solid `gray-400` to the alpha token `gray-alpha-400` (matching the measured official `rgba(0,0,0,.08)` / `rgba(255,255,255,.14)`), so hairlines adapt to the surface behind them and the `.dark` override is no longer needed; the Table header, `bordered` row, and footer hairlines now use the same token (previously `gray-400` was not the same hairline in either theme). (2) `.gridSystem::before` adds `right: var(--guide-width)`: `--width` already narrows the grid by 1px, and without matching the right border it lands 1px past the last column, shifting that column's crosses 1px left. (3) Removes the duplicate `border-bottom` on `[data-grid]`, which shared a pixel row with the frame's bottom edge and stacked the alpha to ~15% against 8% on the other three sides (the old solid color composited to the same value, which is why the duplicate went unnoticed). (4) Raises the dashed rule to `.guide.dashedGuide` because `.guide`'s `border` shorthand resets `border-image` and wins on source order, so light-theme interior guides rendered solid; `.crossLine` also gains the dashed rule, so dashed crosses are no longer always solid.
- **Two docs-shell geometry fixes**: (1) The footer feedback column returns to 48px — `FeedbackPanel`'s section is `inline-flex`, so a block-level container grows a line box and ends up at content height plus font descender space (measured 54px); the middle column now uses `flex` so the section becomes a flex item, the line box disappears, the feedback column equals the capsule's real height (48px), and the nav is sized by prev/next (54→51) while all three columns stay vertically centered; an E2E assertion locks the height. (2) The "Back to Components" link now centers its icon on the glyph rather than the line box — icon and line box were already aligned to 0.00px, but with this font stack CJK glyph padding sits almost entirely above the baseline (measured ascent 13 / descent 2), so geometric centering visibly pushed the icon up; the icon and label now share one `inline-flex` box as their centering reference and gain `whitespace-nowrap` to stop CJK from breaking per character in narrow containers, with a new geometry contract test.
- **`superellipsePath` axis-endpoint precision and demo aspect ratio**: two fixes. (1) The axis-endpoint check used `Number.isInteger(index * 4 / steps)`, which depends on floating-point exactness — at `samples=96` the quotient at index 24 is `0.9999999999999999` rather than `1`, so the check failed and an endpoint that should land exactly on `(a, b)` was replaced by `Math.cos(π/2)≈6.1e-17`, which the `2/n` exponent then amplified into a measurable coordinate drift. It now uses a modulo check (`index % (steps / 4) === 0`) and is unaffected at `samples=8/12/24/48/96`. (2) The `ContinuousSurface` example's superellipse tile moves from `aspect-[4/3]` to `aspect-square`: the function samples `|x/a|^n + |y/b|^n = 1` uniformly **in angle**, so a non-square box stretches the sample distribution and distorts the whole curve; the docs already state that a full superellipse belongs on near-square surfaces, and the demo now matches that guidance. Adds five parameterized endpoint-precision regression tests.
- **Skeleton loading cadence (visual change)**: the default `animate-pulse` (a 2s whole-block opacity breath) is replaced by a **1.4s sweeping shimmer band** (new `--animate-skeleton-shimmer` plus `@keyframes skeleton-shimmer`, translating -100%→100% measured against the element's own width so any skeleton width sweeps exactly once per cycle; the band travels for the first 45% and the surface stays clean for the remaining 55%, leaving a legible repeating cadence instead of constant flashing). The period matches the sibling LoadingDots blink so two loading rhythms never fight on one screen, and the band's horizontal motion states "data is flowing into this region" more explicitly than a brightness change alone. The gradient lives on a decorative `aria-hidden` child rather than an `::after`, so callers overriding the shape through `className` never have to derive pseudo-element sizing. Apple's HIG "Loading" chapter specifies no frame rate or duration — its requirement is to avoid blank waiting, show placeholder content early, and make ongoing work visible, which this change follows; `motion-reduce` still disables the animation entirely.
- **Tabs demos ignored clicks on enabled tabs (fix)**: the `Disable specific tabs`, `With icons`, `Secondary` and `Disabled` demos hard-coded `selected` and passed a no-op `setSelected`, so clicking an enabled tab only moved focus while the selection stayed frozen on the initial value (the official demos all use `useState`). All four now manage selection with `useState`, and the disabled Mango tab in `Disable specific tabs` stays unselectable. A new regression test locks the "clicking an enabled tab switches the selection" contract.
- **Table `Bordered table` renamed (both languages)**: this demo uses `colorScheme="bordered"`, which means **row separators**, while the container outline is owned by `TableRoot`'s `frame` — and it does not wrap in `TableRoot` at all, so the old name (English `Bordered table`, Chinese 带边框表格) described exactly what it does *not* have. It is now `Row dividers` / 行间分隔线表格, consistent with `columnDividers` (列分隔线) and the guide wording, and the `colorScheme` description changed from 带边框 to 行间分隔线 too. The example file `bordered.example.tsx` was renamed to `row-dividers.example.tsx` and now uses the non-deprecated `Table colorScheme="bordered"` instead of `TableBody`'s `bordered`.
- **Feedback topic selector now uses the Select component (visual and accessibility consistency)**: the default Popover's topic dropdown was a native `<select>`, which did not match the material, radius, highlight, and keyboard states of the other selectors in the repository; it now reuses the package `Select` / `SelectItem` (Radix). The `aria-label`, `size="small"`, placeholder copy, and topic localization behavior are unchanged, options are still driven by `topics` / `showTopics`, and the semantics of the fourth `onSubmit` argument (topic) are the same. Unit tests and Playwright cases were moved from native `selectOption` / `toHaveValue` to real trigger and portal-option clicks, and `tests/feedback-i18n.test.tsx` now asserts the `aria-label` of `[data-slot="select-trigger"]`.
- **Feedback support copy and inline dismissal predicate**: the in-form Markdown hint rendered as the truncated `supported.` (identical key and value in both locales, degrading to the bare `支持。` in Chinese) and now reads `Markdown supported.` / `支持 Markdown。`; the Inline capsule's `focusout` no longer conflates a `null` `relatedTarget` with "focus is neither inside the container nor a known target" — it re-checks the real focus target one tick later, so a window blur no longer clears the rating by mistake while genuine focus departure still collapses the capsule.
- **Feedback Inline capsule geometry (visual change)**: fixed the radius snap during expansion — the collapsed `rounded-full` resolves to an effectively-infinite radius, which browsers clamp to `min(w,h)/2`, so roughly 99% of the transition sits at one clamped visual radius and then drops to 12px in a single step; it now uses the new interpolatable semantic token `--radius-capsule-interpolable` (24px = half the 48px collapsed height), measured at `24 → 20.06 → 17.57 → 15.78 → 13.48 → 12px` across the whole transition. Also fixed the expanded right gutter: header content was previously left-packed, leaving 62-69px empty to the right of the emoji row at 336px, and a `flex-1` label now absorbs the surplus so the emoji row sits against the 8px right padding. Collapsed width is now content-sized (`w-fit`) and **the label is never truncated** (Chinese copy goes from 274px with 8px clipped to a fully visible 282.28px), so the collapsed width is no longer pinned to the official 274px and varies slightly by locale; the expanded state stays at 336px.
- **Feedback topic demo (new)**: added a non-`dryRun` `Feedback with topics` demo that renders the actual `onSubmit` arguments (rating / topic / metadata / text) as a receipt after a real submit, making the topic delivery path observable; new Playwright coverage asserts in real Chromium that the topic arrives via the fourth argument without polluting `metadata`, and that a window blur keeps the capsule open while genuine focus departure still collapses it and preserves the draft.
- **Feedback Inline floating card (geometry and animation rework)**: the capsule now renders as an anchor layer (constant 48px) plus an `absolute bottom-0` floating card that grows upward into a popover while the footer layout stays untouched (measured container top Δ-197, bottom/parent height Δ0). Expansion is **horizontally centered on the collapsed capsule's geometric center** — both edges move outward symmetrically (measured center offset 0, +27px per side) — and the header is always `w-fit mx-auto`, centered like the official footer. Width switched from `w-fit` to an explicit measured value (`ResizeObserver` on the header's natural width) because `fit-content` cannot interpolate with a fixed length, which was one root cause of the abrupt collapse; the form region stays mounted and animates height via `grid-rows 0fr→1fr`, so collapsing restores width, height, and radius together along one `cubic-bezier(0.32,0.72,0,1)` curve (frame-by-frame: w 319→297→285→282 tracks h 184→103→60→48 with no snap). The docs Inline demo is now horizontally centered to match the official demo, and the form footer's `bg-gray-100` seam band was removed.
- **Default Feedback Popover now prefers opening upward (visual change)**: the default variant usually sits at the bottom of a page, where a downward popover gets clipped by the viewport edge. It now uses `side="top"` with `avoidCollisions` and a 16px `collisionPadding`, still flipping below automatically when there is not enough room above; width, anchoring, keyboard, and dismissal behavior are unchanged.
